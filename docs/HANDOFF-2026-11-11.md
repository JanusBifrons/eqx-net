## Notes for whoever picks this up

- **Removing a worktree whose `node_modules` is a junction:** unlink the junction FIRST, in PowerShell (`if ((Get-Item $j -Force).Attributes -band [IO.FileAttributes]::ReparsePoint) { cmd /c rmdir "$j" }` with an absolute path), check no reparse points remain, THEN `Remove-Item -Recurse -Force` and `git worktree prune`. A bash `cmd //c rmdir` with a relative path fails silently and `git worktree remove --force` then deletes through the junction into the root `node_modules` (it happened twice; recovery: `pnpm install --frozen-lockfile --offline`).
- **Agents can't run `gh pr merge`.** Auto mode blocks it. The parent session reviews and merges, or puts the PR on a train. Brief agents not to try.
- **Use trains early.** Main requires up-to-date branches, so batch 3–4 reviewed PRs into a `land/train-<date>` branch, disable the members' auto-merge and comment on each one. GitHub then marks the members merged when the train lands (it did for #446–#448).
- **`perf-counts`** failed once on train #449 and passed on CI's automatic retry with every scene in budget. That fits the known loose fleet-fight draw-call budget (consolidated handoff, Perf).
- **Line endings:** `core.autocrlf=true`. The Edit tool can write CRLF into LF files, so normalise with `sed -i 's/\r$//'` and compare the CR count against origin/main before committing. There is no Python on the laptop.
- **Vitest runs can rewrite** `src/core/swarm/__snapshots__/asteroidShape.test.ts.snap` locally. Restore it with `git checkout --` before committing a train.
