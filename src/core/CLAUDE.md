# CLAUDE.md — src/core (The Blind Simulation Zone)

`src/core` is the **blind** zone: it knows about physics, events, and pure logic, and nothing else. It has no idea whether it is running on a server, in a browser, or in a worker thread. That blindness is what lets the same code run authoritatively on the server and predictively on the client.

Start here before editing anything under `src/core/`. The root [CLAUDE.md](../../CLAUDE.md) covers project-wide invariants.

---

## Forbidden Imports (CI-enforced)

Never import any of these from inside `src/core/`:

- UI / rendering: `pixi.js`, `pixi.js/*`, `pixi-viewport`, `react`, `react-dom`, `@mui/*`, `@emotion/*`, `howler`, `zustand`
- Networking concretions: `colyseus`, `colyseus.js`
- Persistence: `better-sqlite3`
- HTTP: `express`, `pino`, `node:http`, `node:https`, `http`, `https`
- Filesystem: `node:fs`, `fs`
- Anything under `src/server/**` or `src/client/**`

Allowed runtime libs: `@dimforge/rapier2d-compat`, `eventemitter3`, `zod` (types), plus the TS stdlib.

Never weaken the forbidden list in `eslint.config.js`: it is the "no web leaks" guarantee the whole architecture depends on. The canary [\_\_fixtures\_\_/leak.ts.disabled](__fixtures__/leak.ts.disabled) proves the rule is live.

## Dependency Inversion — The Contracts Catalogue

`src/core` never instantiates a renderer, audio, network or persistence concretion: it declares interfaces in `src/core/contracts/` and takes implementations by constructor injection. A new concretion is a new contract here, never a reach into the server or client zones.

- **Contracts:** `IRenderer`, `IAudio`, `INetworkSink`, `IPersistenceSink` (closed-set op union; detail: [persistence-and-migrations](../../docs/architecture/persistence-and-migrations.md)).
- **Galaxy graph:** [galaxy/galaxy.ts](galaxy/galaxy.ts) is pure. Its `GALAXY_SECTORS` / `GALAXY_FACTIONS` / `ENTRY_SECTOR_KEYS` literals are GENERATED by `scripts/generate-galaxy.ts`: never hand-edit them; `galaxy/galaxy.test.ts` locks the invariants. Detail: [galaxy-graph](../../docs/architecture/galaxy-graph.md#regenerating-the-galaxy).
- **Entity pipeline:** a new world-object type is a leaf + a descriptor in the append-only `EntityKindRegistry`; `HealthBinding` never copies values; one monomorphic `applyInteraction`, never a per-class `receiveInteraction`; `Entity` is not `AiEntity`. Detail: [generic-entity-pipeline](../../docs/architecture/generic-entity-pipeline.md#zone-split).

## Event Bus Rules (core owns the bus)

- The bus lives at `src/core/events/Bus.ts` as a strongly-typed `eventemitter3` facade.
- All event variants live in a single discriminated union. Adding one = adding a variant.
- **Discrete events only.** Never add `POSITION_UPDATED`, `VELOCITY_CHANGED`, `TICK_ADVANCED`, or anything per-frame. Continuous data flows via polling, not emits.
- Never emit in a tight loop: use direct state mutation / SAB writes.

## Physics Rules

- `world.step(1/60)` inside a `while (accumulator >= fixedDt)` accumulator loop. No variable-dt stepping, ever.
- Rapier bodies / colliders are pooled; do not allocate per-tick.
- **Ship stats belong to the kind, never the pilot:** mass and inertia only from `shipBodyMass` / `shipBodyInertia`.
- Sleep callbacks drive `ENTITY_SLEPT` / `ENTITY_WOKE`: do not suppress or re-enter them without thinking about the handshake.
- **Spawned bodies:** drones get their kind's `linearDamping` (the client predWorld drone body stays undamped, anchored each snapshot); asteroids stay ballistic; structures (kind 2) are LOCKED on spawn (`staticBody` → `lockBody`), as in the client predWorld. Locks: `World.test.ts`, `SwarmSpawner.test.ts`, `structure-ram-blocked.spec.ts`.
- **Soft CCD on every dynamic body** (`SOFT_CCD_PREDICTION`); never switch to full `setCcdEnabled(true)` (`World.ccd.test.ts`).
- **Handling feel is tuned per class** in `shared-types/shipScale/arcadeHandling.ts`, never per record (`ShipHandling.arcade.test.ts`).
- **Capitals collide through `CapitalOverlapResolver`** (capital bodies only); never replace it with a global `lengthUnit` change (`World.capitalContact.test.ts`).
- **Stiff solver** (`numSolverIterations = 16` + `switchToSmallStepsPgsSolver()`): never revert to Rapier defaults without measuring `tests/e2e/ramming-probe-armpit.spec.ts`.
- Detail: [ship-physics-handling](../../docs/architecture/ship-physics-handling.md#physics-rules-reference).

## Structure footprints, gates and the scale lattice

- **Footprints:** every gameplay rule (collision, placement, grid edge distance, line of sight, weapon hits) tests the `footprint` box (`structureHalfExtents`, `rayHitsBox`, ...); `radius` is for broad checks only, never a gameplay rule. Detail: [structure-network-scale](../../docs/architecture/structure-network-scale.md#phase-v-structures-redesigned-far-larger).
- **Gates (#15):** gate parts, spans, anchors and approach zones come only from `structures/gateGeometry.ts`; never hand-place a post or span. Open/close is server-only (`gateLogic.ts`); an airlock stays ONE `phase` field so both ends can never be open. Detail: [structures-and-power-grid](../../docs/architecture/structures-and-power-grid.md#gates).
- **Generated bases pass the real rules:** `structures/structureLattice.ts` and the base generator never bypass `placementRejection` / `canConnect` (`structureLattice.test.ts`, `growBase.test.ts`). Budgets: `src/shared-types/structureBudgets.ts`.

## Physics Worker — Input Queue Contract

[physics/inputQueue.ts](physics/inputQueue.ts) runs once per slot per step from `physics/worker.ts`. Four rules, all locked by `physics/inputQueue.test.ts`; read [physics-worker](../../docs/architecture/physics-worker.md#input-queue-contract) before changing any:

1. **Tick-gated dequeue:** apply the head only when `head.tick ≤ currentTick`, ack = its tick. Never drain greedily.
2. **Future claim (`head.tick > currentTick`) → hold**, as if the queue were empty.
3. **Queue empty or gated + held input → re-apply the held input AND advance the ack by 1.** Never pin the ack to the last received message.
4. **One sim step = one acked tick:** a late input (its tick already simulated) becomes the held input; it never gets a step of its own.

## GameClock: game time is the default

- Gameplay and presentation read `clock/GameClock.ts` (0.25–4×, `after` / `every` timers re-armed on a speed change). Core never builds one: take an injected `Clock` or a `nowMs` argument.
- `Date.now` / `performance.now` / `setTimeout` / `setInterval` in core are a LINT ERROR outside the real-time allowlist in `eslint.config.js`. Detail: [game-time-scale](../../docs/architecture/game-time-scale.md).

## SimulationClock

- `clock/SimulationClock.ts`: pure, takes only an optional `Bus`; `rate ∈ [0.7, 1.0]`. The server constructs and owns it; `src/core` never instantiates it (DI invariant #5).
- **Rate and shedding:** the rate feeds `LoadSpeedController` (sector game speed), never the worker step directly; `ENTITY_SHED` (budget eviction) stays distinct from `ENTITY_DESTROYED` (killed). Detail: [game-time-scale](../../docs/architecture/game-time-scale.md#simulationclock-reference).

## Physics Worker — worlds and messages

- **One worker, many worlds:** each sector world lives in its `createWorld(sab, post)` closure; never put per-sector state at module scope in `worker.ts`.
- **Worker→main messages** are `READY`, `SLEEP_TRANSITION` and `CONTACT_BATCH`. A new variant extends the worker's `postMessage` site and the SectorRoom handler's `msg.type` discriminator. Keep the `WorkerCommand` union, `SectorRoom.WorkerCmd` and the guide's command list in sync.
- **AI pilot keys are held** every step until the next `AI_INPUTS` (`aiInputHeld`); a bot warp flies its spool on them.
- **Impact damage reads `normalSpeed` and the body masses** (`combat/Ramming.ts`), never post-step velocity.
- Detail: [physics-worker](../../docs/architecture/physics-worker.md#worker-to-main-messages).

## WeaponMountController contract (Phase 4, 2026-05-11)

Pure module at [src/core/ai/WeaponMountController.ts](ai/WeaponMountController.ts) — zero zone awareness, zero I/O, zero allocation in the hot path. Same inputs ⇒ same outputs on server and client (the foundation of mount-angle lockstep).

- **Lockstep picks:** server and client iterate `targets` in the same order (ties go to the first); `prevTargetId` lives on the caller; hostility is an `(id) => boolean` or a per-target `hostile` flag giving the same answer on both sides. Detail: [weapon-mounts](../../docs/architecture/weapon-mounts.md#core-contract-reference).
- **Extend, don't branch:** a smarter pick policy extends `MountTargetView` / `PickTargetOptions`, never the call sites; absent options stay byte-identical (lock `WeaponMountController.test.ts`).
- **Same player-aim options both sides:** client `tickLocalMountAim` and server `WeaponMountTicker.tickPlayer` pass identical options (`PLAYER_AIM_HEALTH_WEIGHT` / `PLAYER_AIM_SWITCH_MARGIN`, Invariant #12). Never add a second mount-angle correction path ([weapon-mounts](../../docs/architecture/weapon-mounts.md#lockstep--correction-paths)).

## AI lockstep — Input Symmetry Rule

- **Input symmetry:** every field a shared client/server brain (`IAiBehaviour`) reads flows on the same channel at the same cadence on both sides; a new behaviour-visible field needs a wire-format bump. Drones are snapshot-interpolated (no client drone brain; `AiController.tick` is server-only), so this governs any future shared brain and the `damage`/`bot_aggro` → `markHostile` mirror. Detail: [ai-lockstep](../../docs/architecture/ai-lockstep.md#input-symmetry-reference), [drone-snapshot-interpolation](../../docs/architecture/drone-snapshot-interpolation.md).
- **One correction path per state surface:** a new correction path for state that already has one must remove or gate the old one. Lock: [`tests/e2e/feel-test-lockstep.spec.ts`](../../tests/e2e/feel-test-lockstep.spec.ts).
- **Hunters reuse `markHostile`; do NOT add an AI-only behaviour path:** a Living World hunter is a drone made hostile through the existing `markHostile` / `bot_aggro` channel. Never add a `proactive` (or any new) `HostileDroneBehaviour` branch, nor a per-drone behaviour flag on the swarm wire. Detail: [living-world](../../docs/architecture/living-world.md).

## Rapier `castRay` API

- Before calling `world.castRay`, read [collision-layers § Rapier castRay API](../../docs/architecture/collision-layers.md#rapier-castray-api) (exclude takes a `RigidBody`; `hit.collider` is a `Collider`; `hit.timeOfImpact`, not `toi`).
- **Query pipeline lag**: `castRay` queries the Rapier broadphase/narrowphase, which is only updated inside `world.step()`. Bodies spawned after the last `step()` are invisible to `castRay`. In unit tests, call `world.tick(1/60)` in `beforeEach` after spawning bodies, before any hitscan calls.

## What belongs in src/core

Pure simulation: physics, AI, combat math, reconciliation, the event bus, DI contracts, shared math, deterministic state machines (e.g. `TransitStateMachine`), leveling curves and grid logic. Rules for those modules:

- **AI pilots use a player's controls only:** a brain picks a facing and a wanted velocity; `ai/virtualPilot.ts` turns them into `AiIntent.input` keys run through `applyShipInput`. Never add an AI-only actuation path; difficulty is reaction and aim, never weaker engines (`ai/virtualPilot.test.ts`). RTS owned hulls fly this same brain (players side).
- **Combat AI** extends `HostileDroneBehaviour` + `ai/tactics/` only; mass-dependent numbers come from the live kind. Detail: [ai-dogfight](../../docs/architecture/ai-dogfight.md).
- **AI distances are multiples of the ship's own numbers** (fire range, `maxSpeed`, `shipTuning`, #18), AI scratch is class fields (#14), and combat movement uses `ai/contextSteering.ts`, never summed weighted vectors. Detail: [ai-pilots](../../docs/architecture/ai-pilots.md), [allegiances](../../docs/architecture/allegiances.md).
- **Leveling** (`leveling/`): the server is the only authority that runs it; `STAT_IDS` is append-only. Physics stats enter ONLY through `applyShipInput(body, kind, input, mul?)`, driven identically on worker and predWorld; caps go through the one `effectiveShip*` / `effectiveStructureMaxHealth` helper. Detail: [leveling-and-upgrades](../../docs/architecture/leveling-and-upgrades.md).
- **Power grid** (`structures/`): works over `GridNode`, never the server registry; an unbuilt node is never traversable; `Grid.powerSummaryFor` stays instantaneous. Detail: [structures-and-power-grid](../../docs/architecture/structures-and-power-grid.md#the-power-grid-phase-3--shipped).
- **Weapons:** `combat/WeaponCatalogue.ts` is the append-only, pure source (`WEAPON_IDS`). Never branch on weapon id in core; a new weapon is a catalogue row. Energy uses the same `combat/Energy.ts` helpers on both sides. An AI-flown ship pays boost and weapons from one pool, via `IAiBehaviour.trySpendEnergy` ([fire-control](../../docs/architecture/fire-control.md#ai-pilot-weapon-energy)). Detail: [weapon-mounts](../../docs/architecture/weapon-mounts.md#weapon-catalogue-fire-classes-and-energy-core).
- **One source each (#15):** `combat/mountReach.ts` `mountTargetReach` is the target-pick radius for both sides; `NAVAL_SHELL_WEAPON_IDS` is the naval list; a shell path ends at `shellPathEndTick(t, n)`, never `t + n` ([shell-events](../../docs/architecture/shell-events.md#slice-1-as-built-2026-11-11)).

## What does NOT belong in src/core

- Anything that reads/writes files.
- Anything that knows about WebSockets.
- Anything that draws pixels or plays sound.
- Anything that calls React or MUI.
- Anything that depends on `performance.now()` vs `process.hrtime()` — abstract time via an injected clock.

## Shield/Hull collider model (2026-05-16)

- `src/core/combat/ShieldHull.ts` is **SERVER-AUTHORITY-ONLY** — unlike
  the shared `HostileDroneBehaviour` brain, the client must NEVER run
  its damage/regen functions (predicting the 0-cross flaps the collider
  every RTT). It lives in core only for testability; a banner says so.
- **Hull colliders are Rapier `triangle`s, never `convexHull`/`cuboid`:** only triangles fire contact-force events on static overlap. Lock: `src/core/physics/hullCollisionNoTouch.test.ts` (DIAGNOSTIC) + the `hull-collision-test` spec. Hull parts come from `geometry/shipHullDecomp.ts`, precomputed at module load, never per tick.
- **Collider swaps:** ship/drone colliders are density 0 with pinned `setAdditionalMassProperties`; call `recomputeMassPropertiesFromColliders()` after every collider change; never `updateSceneQueries()` (diverges from client predWorld).
- **Player fire range is per mount to the target's hit shape:** both sides gate each mount with `combat/fireControlBearing.ts` `mountFiresOn` (range via the shared `mountReach.ts` `mountInReach` + bearing) on a target filled by `fillFireTargetShape`; never a centre-to-centre range check or a reach number of its own (reach = `mountWeaponReach`). Detail: [fire-control](../../docs/architecture/fire-control.md#range-to-the-hull-not-the-centre-player-fire-gate).
- **A ship's weapon hit shape is `combat/shipHitShape.ts`, by kind and shield state, never by pilot;** every server weapon path and the client hit prediction call it; never hit-test on `rec.radius` or a tuning `hitRadius`. Lock: `tests/integration/sectorRoom/shipHitShapeParity.test.ts`. Detail: [collision-layers](../../docs/architecture/collision-layers.md#core-rules-reference).

## Composite ships + scrap geometry

- **Every collision/physics reader of a ship outline goes through `shipHullOutline(kind)`** (`geometry/shipHullOutline.ts`); a composite's collider is its authored `hull`, its `parts[]` are visual only.
- Scrap groups come only from `geometry/shipScrapGroups.ts` (server death path and client `buildScrapGfx` both read it); scrap uses `SCRAP_COLLISION_GROUPS`; tuning lives in `swarm/scrapConstants.ts`. Detail: [composite-ships-and-scrap](../../docs/architecture/composite-ships-and-scrap.md#core-reference).

## Capital fracture (`src/core/destruction/fractureHull.ts`)

- **Deterministic, run on both sides from the same inputs (#15), no geometry on the wire:** arithmetic and `Math.sqrt`/`round` only (never sin/cos/atan2/pow), the mulberry32 `Rng`, fixed loop order, `FRACTURE_QUANTUM` vertices, only `quickDecomp`/`makeCCW` from poly-decomp. Any output change (including a new seeded draw) bumps `FRACTURE_ALGO_VERSION`; concave hulls go through `splitByLine`.
- **One source each:** `wreckPieceGeometry` is a piece's only shape (lock `tests/integration/wire/wreckGeometryParity.test.ts`); `wreckRayHit`/`wreckSweepHit` are the only weapon-vs-wreck test, gated by `segmentNearCircle`, never `rayHitsSphere` (`wreckHits.test.ts`).
- **Wrecks:** never give pieces a velocity field that closes a cut (`wreckPiecesSeparate.test.ts`). Per-profile numbers live in `DESTRUCTION_PROFILES`, never a branch; new `fractureHull` options default to old behaviour (`fractureHull.subcap.test.ts`). Detail: [capital-destruction](../../docs/architecture/capital-destruction.md#core-rules-reference).

## Alien gates and the disabled input gate

- `galaxy/alienGates.ts` is the one source for gate sites and their owner (`alienGateSites`, `alienGateCandidates`, `ALIEN_GATE_OWNER`).
- `combat/disable.ts` `gateDisabledInput` is the disabled-input contract for BOTH sides (#15). Never copy its logic; `tests/unit/disableParity.test.ts` fails if either side stops calling it. Detail: [alien-gates](../../docs/features/alien-gates.md).

## Relations: one answer to "who is hostile to whom"

- **Ask `relationOf(actor, owner, ctx)`** (`src/shared-types/relations.ts`) whenever a system decides whether a ship is welcome near something it doesn't own; never compare owners or allegiances inline.
- Owners are built/read by `npcOwner` / `parseOwner`; only `FactionPolicy` turns standing into behaviour; hostile acts go into `HostileActLedger`.
- **Keep one `RelationContext` per room** and update `nowMs` in place; the query allocates nothing. Detail: [relations](../../docs/architecture/relations.md), [factions](../../docs/architecture/factions.md).

## Production chain data

- **Goods, recipes and asteroid kinds live in `src/shared-types/`**. `recipes.test.ts` is the authority over balance: a price or recipe change must still pass it; never loosen it.
- **`GOOD_IDS`, `RECIPE_IDS` and `ASTEROID_RESOURCE_IDS` are append-only** (persisted or on the wire). Detail: [production-chains](../../docs/architecture/production-chains.md#rules-locked-by-srcshared-typesrecipestestts).

## Base generator (`src/core/bases/`)

- **Deterministic per seed:** bump `BASE_GROWTH_VERSION` on any output change. A new random choice uses its OWN seeded stream so existing rolls never shift.
- **Fenced bases put their turrets on bastions OUTSIDE the fence**; `Builder.tryPlace` refuses any box on a link line.
- **Count guns with `TURRET_KINDS`,** never a name regex. Capital mounts and defence structures share `combat/mountFireControl.ts`; structure naval guns use `structureNavalTurret` / `structureMountMuzzle` (#15).
- Player-facing text says "habitat station", never "city".
- Detail: [production-chains](../../docs/architecture/production-chains.md#base-roles-and-the-growth-generator-d1), [coastal-defences](../../docs/features/coastal-defences.md#in-the-bases).
