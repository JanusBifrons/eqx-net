# CLAUDE.md — src/core (The Blind Simulation Zone)

`src/core` is the **blind** zone: physics, events and pure logic only. It never knows whether it runs on a server, in a browser or in a worker, so the same code runs authoritatively on the server and predictively on the client. Project-wide invariants: root [CLAUDE.md](../../CLAUDE.md).

---

## Forbidden Imports (CI-enforced)

Never import from inside `src/core/`:

- UI / rendering: `pixi.js`, `pixi.js/*`, `pixi-viewport`, `react`, `react-dom`, `@mui/*`, `@emotion/*`, `howler`, `zustand`
- Network: `colyseus`, `colyseus.js` · Persistence: `better-sqlite3` · Filesystem: `node:fs`, `fs`
- HTTP: `express`, `pino`, `node:http`, `node:https`, `http`, `https`
- Anything under `src/server/**` or `src/client/**`

Allowed runtime libs: `@dimforge/rapier2d-compat`, `eventemitter3`, `zod` (types), the TS stdlib. Never weaken the forbidden list in `eslint.config.js` (the "no web leaks" guarantee); the canary [\_\_fixtures\_\_/leak.ts.disabled](__fixtures__/leak.ts.disabled) proves it is live.

## Dependency Inversion — The Contracts Catalogue

Core never instantiates a renderer, audio, network or persistence concretion: it declares an interface in `src/core/contracts/` and takes the implementation by constructor injection. A new concretion is a new contract here, never a reach into server or client.

- **Contracts:** `IRenderer`, `IAudio`, `INetworkSink`, `IPersistenceSink` (closed-set op union; [persistence-and-migrations](../../docs/architecture/persistence-and-migrations.md)).
- **Galaxy graph:** [galaxy/galaxy.ts](galaxy/galaxy.ts) is pure; its `GALAXY_SECTORS` / `GALAXY_FACTIONS` / `ENTRY_SECTOR_KEYS` literals are GENERATED by `scripts/generate-galaxy.ts`, never hand-edited (`galaxy/galaxy.test.ts`). [galaxy-graph](../../docs/architecture/galaxy-graph.md#regenerating-the-galaxy).
- **Entity pipeline:** a new world-object type = a leaf + a descriptor in the append-only `EntityKindRegistry`; `HealthBinding` never copies values; one monomorphic `applyInteraction`, never per-class `receiveInteraction`; `Entity` is not `AiEntity`. [generic-entity-pipeline](../../docs/architecture/generic-entity-pipeline.md#zone-split).

## Event Bus Rules (core owns the bus)

- The bus is `src/core/events/Bus.ts`, a typed `eventemitter3` facade; all events are one discriminated union (a new event = a new variant).
- **Discrete events only:** never `POSITION_UPDATED`, `VELOCITY_CHANGED`, `TICK_ADVANCED` or anything per-frame; continuous data is polled. Never emit in a tight loop: use direct state mutation / SAB writes.

## Physics Rules

- `world.step(1/60)` inside a `while (accumulator >= fixedDt)` loop; never variable-dt stepping. Rapier bodies / colliders are pooled; no per-tick allocation.
- **Ship stats belong to the kind, never the pilot:** mass and inertia only from `shipBodyMass` / `shipBodyInertia`.
- Sleep callbacks drive `ENTITY_SLEPT` / `ENTITY_WOKE`: never suppress or re-enter them without the handshake in mind.
- **Spawned bodies:** drones take their kind's `linearDamping` (client predWorld drone body stays undamped); asteroids are ballistic; structures (kind 2) are LOCKED on spawn, as in the predWorld.
- **Soft CCD on every dynamic body** (`SOFT_CCD_PREDICTION`), never full `setCcdEnabled(true)`. **Handling feel is per class** (`shared-types/shipScale/arcadeHandling.ts`), never per record.
- **Capitals collide through `CapitalOverlapResolver`**, never a global `lengthUnit` change. **Stiff solver** (16 iterations + `switchToSmallStepsPgsSolver()`): never revert without measuring `tests/e2e/ramming-probe-armpit.spec.ts`.
- Why and the locking tests: [ship-physics-handling](../../docs/architecture/ship-physics-handling.md#physics-rules-reference).

## Structure footprints, gates and the scale lattice

- **Footprints:** every gameplay rule (collision, placement, grid edge distance, line of sight, weapon hits) tests the `footprint` box (`structureHalfExtents`, `rayHitsBox`); `radius` is for broad checks only. [structure-network-scale](../../docs/architecture/structure-network-scale.md#phase-v-structures-redesigned-far-larger).
- **Gates:** parts, spans, anchors and approach zones come only from `structures/gateGeometry.ts`; open/close is server-only (`gateLogic.ts`); an airlock is ONE `phase` field so both ends can never be open. [structures-and-power-grid](../../docs/architecture/structures-and-power-grid.md#gates).
- **Generated bases pass the real rules:** `structureLattice.ts` and the base generator never bypass `placementRejection` / `canConnect`. Budgets: `src/shared-types/structureBudgets.ts`.

## Physics Worker — Input Queue Contract

[physics/inputQueue.ts](physics/inputQueue.ts): apply the head only when `head.tick ≤ currentTick` (never drain greedily); hold a future claim; with the queue empty or gated, re-apply the held input AND advance the ack by 1 (never pin it); one sim step = one acked tick (a late input becomes the held input). Locked by `inputQueue.test.ts`; read [physics-worker](../../docs/architecture/physics-worker.md#input-queue-contract) before changing any.

## GameClock: game time is the default

- Gameplay and presentation read `clock/GameClock.ts`; core never builds one: take an injected `Clock` or a `nowMs` argument.
- `Date.now` / `performance.now` / `setTimeout` / `setInterval` in core are a LINT ERROR outside the real-time allowlist in `eslint.config.js`. [game-time-scale](../../docs/architecture/game-time-scale.md).

## SimulationClock

- `clock/SimulationClock.ts` is pure (optional `Bus` only); the server constructs and owns it, core never does (DI invariant #5).
- Its rate feeds `LoadSpeedController`, never the worker step; `ENTITY_SHED` (budget eviction) stays distinct from `ENTITY_DESTROYED`. [game-time-scale](../../docs/architecture/game-time-scale.md#simulationclock-reference).

## Physics Worker — worlds and messages

- **One worker, many worlds:** per-sector state lives in its `createWorld(sab, post)` closure, never at module scope in `worker.ts`.
- **Worker→main** (`READY`, `SLEEP_TRANSITION`, `CONTACT_BATCH`): a new variant extends the `postMessage` site and the SectorRoom `msg.type` handler. Keep `WorkerCommand`, `SectorRoom.WorkerCmd` and the guide's command list in sync.
- **AI pilot keys are held** every step until the next `AI_INPUTS`. **Impact damage reads `normalSpeed` and body masses** (`combat/Ramming.ts`), never post-step velocity. [physics-worker](../../docs/architecture/physics-worker.md#worker-to-main-messages).

## WeaponMountController contract

[ai/WeaponMountController.ts](ai/WeaponMountController.ts) is pure (no I/O, no hot-path allocation): same inputs ⇒ same outputs on both sides. [weapon-mounts](../../docs/architecture/weapon-mounts.md#core-contract-reference).

- **Lockstep picks:** both sides iterate `targets` in the same order (ties to the first); `prevTargetId` lives on the caller; hostility answers the same on both sides.
- **Extend, don't branch:** a smarter pick policy extends `MountTargetView` / `PickTargetOptions`; absent options stay byte-identical (`WeaponMountController.test.ts`).
- **Same player-aim options both sides** (`tickLocalMountAim` / `WeaponMountTicker.tickPlayer`, Invariant #12). Never add a second mount-angle correction path.

## AI lockstep — Input Symmetry Rule

- **Input symmetry:** every field a shared client/server brain (`IAiBehaviour`) reads flows on the same channel at the same cadence both sides; a new behaviour-visible field needs a wire-format bump. [ai-lockstep](../../docs/architecture/ai-lockstep.md#input-symmetry-reference).
- **One correction path per state surface:** a new one must remove or gate the old (`tests/e2e/feel-test-lockstep.spec.ts`).
- **Hunters reuse `markHostile` / `bot_aggro`:** never a new `HostileDroneBehaviour` branch or a per-drone behaviour flag on the swarm wire. [living-world](../../docs/architecture/living-world.md).

## Rapier `castRay` API

Read [collision-layers § Rapier castRay API](../../docs/architecture/collision-layers.md#rapier-castray-api) before calling `world.castRay`. Bodies spawned after the last `step()` are invisible to it: in unit tests, `world.tick(1/60)` after spawning, before any hitscan.

## What belongs in src/core

Pure simulation: physics, AI, combat math, reconciliation, the bus, DI contracts, shared math, deterministic state machines, leveling and grid logic. Never: file I/O, WebSockets, pixels or sound, React / MUI, or a direct clock (`performance.now()` / `process.hrtime()`: inject a clock).

- **AI pilots use a player's controls only:** a brain picks facing + wanted velocity; `ai/virtualPilot.ts` turns them into keys through `applyShipInput`. No AI-only actuation; difficulty is reaction and aim, never weaker engines.
- **Combat AI** extends `HostileDroneBehaviour` + `ai/tactics/` only; mass numbers come from the live kind ([ai-dogfight](../../docs/architecture/ai-dogfight.md)). **AI distances are multiples of the ship's own numbers** (#18), scratch is class fields (#14), combat movement uses `ai/contextSteering.ts` ([ai-pilots](../../docs/architecture/ai-pilots.md)).
- **Leveling** is server-run; `STAT_IDS` append-only. Physics stats enter ONLY through `applyShipInput(body, kind, input, mul?)`, same on worker and predWorld; caps via the one `effectiveShip*` / `effectiveStructureMaxHealth` helper. [leveling-and-upgrades](../../docs/architecture/leveling-and-upgrades.md).
- **Power grid** works over `GridNode`, never the server registry; an unbuilt node is never traversable; `Grid.powerSummaryFor` stays instantaneous. [structures-and-power-grid](../../docs/architecture/structures-and-power-grid.md#the-power-grid-phase-3--shipped).
- **Weapons:** `combat/WeaponCatalogue.ts` is the append-only source (`WEAPON_IDS`); never branch on weapon id in core. Energy uses `combat/Energy.ts` on both sides; an AI-flown ship pays boost and weapons from one pool (`IAiBehaviour.trySpendEnergy`). [weapon-mounts](../../docs/architecture/weapon-mounts.md#weapon-catalogue-fire-classes-and-energy-core).
- **One source each (#15):** `mountTargetReach` (`combat/mountReach.ts`) is the pick radius; `NAVAL_SHELL_WEAPON_IDS` the naval list; a shell path ends at `shellPathEndTick(t, n)`, never `t + n`. [shell-events](../../docs/architecture/shell-events.md).

## Shield/Hull collider model

- `combat/ShieldHull.ts` is **SERVER-AUTHORITY-ONLY**: the client never runs its damage/regen (it lives in core for testability).
- **Hull colliders are Rapier `triangle`s**, never `convexHull`/`cuboid`; parts from `geometry/shipHullDecomp.ts` at module load. **Collider swaps:** density 0 + pinned mass, `recomputeMassPropertiesFromColliders()` after each change, never `updateSceneQueries()`. [collision-layers](../../docs/architecture/collision-layers.md#core-rules-reference).
- **Fire range is per mount to the target's hit shape:** both sides gate with `mountFiresOn` (`combat/fireControlBearing.ts`) on `fillFireTargetShape`; never centre-to-centre or a reach of its own. [fire-control](../../docs/architecture/fire-control.md#range-to-the-hull-not-the-centre-player-fire-gate).
- **A ship's weapon hit shape is `combat/shipHitShape.ts`, by kind and shield state, never pilot;** never hit-test on `rec.radius` or `hitRadius` (`shipHitShapeParity.test.ts`).

## Composite ships + scrap geometry

- **Every collision/physics reader of a ship outline uses `shipHullOutline(kind)`**; a composite's collider is its `hull`, `parts[]` are visual only.
- Scrap groups come only from `geometry/shipScrapGroups.ts` (server and client); scrap uses `SCRAP_COLLISION_GROUPS`; tuning in `swarm/scrapConstants.ts`. [composite-ships-and-scrap](../../docs/architecture/composite-ships-and-scrap.md#core-reference).

## Capital fracture (`destruction/fractureHull.ts`)

- **Deterministic both sides, no geometry on the wire (#15):** arithmetic + `Math.sqrt`/`round` only (no sin/cos/atan2/pow), mulberry32 `Rng`, fixed loop order, `FRACTURE_QUANTUM`, only `quickDecomp`/`makeCCW`. Any output change bumps `FRACTURE_ALGO_VERSION`; concave hulls go through `splitByLine`.
- **One source each:** `wreckPieceGeometry` is a piece's shape; `wreckRayHit`/`wreckSweepHit` the only weapon-vs-wreck test (gated by `segmentNearCircle`, never `rayHitsSphere`).
- Never give pieces a velocity that closes a cut; per-profile numbers in `DESTRUCTION_PROFILES`, never a branch; new options default to old behaviour. [capital-destruction](../../docs/architecture/capital-destruction.md#core-rules-reference).

## Alien gates and the disabled input gate

- `galaxy/alienGates.ts` is the one source for gate sites and owner. `combat/disable.ts` `gateDisabledInput` is the disabled-input contract for BOTH sides (#15); never copy it (`disableParity.test.ts`). [alien-gates](../../docs/features/alien-gates.md).

## Relations: one answer to "who is hostile to whom"

- **Ask `relationOf(actor, owner, ctx)`** (`src/shared-types/relations.ts`); never compare owners or allegiances inline. Owners via `npcOwner` / `parseOwner`; only `FactionPolicy` turns standing into behaviour; hostile acts go into `HostileActLedger`.
- **One `RelationContext` per room**, `nowMs` updated in place; the query allocates nothing. [relations](../../docs/architecture/relations.md), [factions](../../docs/architecture/factions.md).

## Production chain data

- Goods, recipes and asteroid kinds live in `src/shared-types/`; `recipes.test.ts` is the balance authority, never loosened. `GOOD_IDS`, `RECIPE_IDS`, `ASTEROID_RESOURCE_IDS` are append-only. [production-chains](../../docs/architecture/production-chains.md#rules-locked-by-srcshared-typesrecipestestts).

## Base generator (`src/core/bases/`)

- **Deterministic per seed:** bump `BASE_GROWTH_VERSION` on any output change; a new random choice gets its OWN seeded stream.
- **Fenced bases put turrets on bastions OUTSIDE the fence**; `Builder.tryPlace` refuses a box on a link line. **Count guns with `TURRET_KINDS`,** never a name regex; capital mounts and defence structures share `combat/mountFireControl.ts`; structure naval guns use `structureNavalTurret` / `structureMountMuzzle`.
- Player-facing text says "habitat station", never "city". [production-chains](../../docs/architecture/production-chains.md#base-roles-and-the-growth-generator-d1), [coastal-defences](../../docs/features/coastal-defences.md#in-the-bases).
